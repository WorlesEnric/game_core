## Repairs and why

1. `WorldObservation.cs`: import `GameCore.Execution.Messages` to resolve `CommittedEventStore` in pure .NET build (three CS0246 errors). `DiagnosticEnvelope.cs`, `ProvenanceRecords.cs`, `StagedOperationStatus.cs`: remove four illegal `?? ContentHash.Empty` expressions on the nonnullable `ContentHash` value type (CS0019). No default semantics changed.
2. `DiagnosticPrecedence.Compare`: within a phase compare stable diagnostic-code literals ordinally, not enum allocation numbers; formatting remains excluded from precedence. This fixes the `Ineligible`/`StalePlan` ordering failure without altering frozen enums.
3. `StepPublicationStore.Publish` and `TryResync`: synchronize complete retained-image insertion and published pointer movement under the same gate used by readers, eliminating a possible pointer/retention mismatch. `PublishedStepImage.PayloadHash` remains SHA-256 of the frozen bytes; `CommittedBoundaryLease.Verify()` independently recomputes SHA-256 from the leased bytes. This is important: the published bytes currently contain the already-hashed `StateHash` fingerprint, so payload SHA-256 differs from `StateHash`. One earlier proposed fix equated the two and made the real-world hash test fail; the final fix preserves independently verifiable integrity. Observation fixture expected digest now hashes those bytes while separately testing the semantic `StateHash`. No hash assertion was removed.
4. `ConcurrentObservationTests`: publish the initial image before readers start. Previously readers could complete all 400 iterations before the publisher's first write, giving zero acquired images and a false scheduling-dependent failure; readers still race 119 further publications.
5. `ProvenanceExplanationReaderTests`: add the missing successful retained-page read before checking `PageCount == 1`; expired/unknown/invalid reads correctly produce no retained page. `StagedOperationStatusTests`: correct the refused-admission expectation: its public `Plan` is null by contract, while the ledger retains the rejected plan and its diagnostics. The test now asserts both facts; no test disabled or expected semantic outcome weakened. The earlier false expected values were contradicted by the refusal API and other established tests; P-028/P-029 require rejection before publication, and P-052 diagnostics remain inspectable.

`artifacts/gates/w4-generic-profile/inventory.{md,json}` cites the executed GC-016 evidence for P-007, P-026, P-045, P-050 and P-052; all five remain **Partial**, and inventory counts are unchanged. No unsupported status promotion. Outstanding V1 scope includes checkpoint/restore, crash-durable external outbox, unified cross-module diagnostics and full load/benchmark evidence (see inventory gaps). Unity's successful EditMode log reports `Leak Detected : Persistent allocates 57 individual allocations` during Editor shutdown without allocation stack traces; this run did not attribute those allocations or establish a per-test memory baseline. A passing suite does not establish TEST-023 lifecycle leak conformance. No execution was blocked or NotRun among the commands listed above.
