## Defects found and fixed

1. First dotnet build exposed ten errors: nullable JSON node text, missing array-length accessor, misplaced recovery fault-point conversion helper, and a nonexistent outbox cursor property. Repaired those expressions without changing fixture values. The first dotnet test then found a `default(StoredCheckpoint).IsStored` null dereference and a fixture vocabulary test that compared only referenced boundaries against all 13 declared latch names; fixed the default check and compared the complete declared boundary set. Initial test run 1,156/1,163; final 1,163/1,163.
2. Unity compile exposed a delegate/property identifier collision, a missing `out RestoreOutcome?` argument, missing composition/pipeline namespace imports, and an undefined source-world step counter. Fixed the source declarations. The first executable GC-027 run showed capture had frozen outbox rows before the obligation was committed. Refreshing its capture context at the committed boundary carries the real open row and an acknowledged predecessor cursor (four rows total) rather than claiming a cursor that did not exist.
3. Recovery's staging builder built a delivery owner but its public property was never assigned. Exposing the owned field allows `IRestoreOutboxBuilder` to reinstate/prove the rows before exposure. The scenario tested recovered-session liveness before assigning the recovered session; moved the assignment before the predicate. Its before-ack crash had driven delivery but never the separate acknowledgement hook; now it invokes the actual `TryAcknowledge` boundary. Removed incorrect hook reach-count assertions while retaining boundary membership, crash, redelivery, single-effect and settled-state checks. The store-read mechanism is distinct from a latch in the Unity vocabulary test; its expected value was corrected to the documented `store-read` (no weakening of the recovery behavior).
4. Real traversal capture initially dropped pose, velocity and accepted progress; a player showed recovered runners as `absent` despite a superficially passing physics reseed of zero-valued state. The traversal family now persists its real ECS fields into **declared stable owner-slot rows** after its admitted step, and reconstructs them solely from the checkpoint plan into the new world's ECS before exposure. Missing fields refuse. The existing planner requires every live slot declared, so the traversal manifest gained 17 durable projection declarations per runner; it retains one owner and no new physical writer. The player now reports 53 restored slots (52 dormant), three authoritative runner states equal across sessions, and new disjoint native indices. Fixed the fixed-step observation's mistaken command-driven idle-zero assertion. The EditMode traversal test enters Play Mode for the real local `PhysicsScene` because Unity refuses `SceneManager.CreateScene` in Edit Mode; the full EditMode suite passed after that change.
5. A passing `-probeRecovery` JSON initially preceded SIGSEGV/exit 139 in **5/5** runs. GDB reproduced the native fault after the report; symbolication of the matching `UnityPlayer_s.debug` at offsets `0x143897f`, `0x131a58b`, `0x1319787`, `0x1318bf8` identified `PhysicsManager::DestroyPhysicsScene`, `UnityScene::~UnityScene`, `RuntimeSceneManager::~RuntimeSceneManager`, `StaticDestroyRuntimeSceneManager`. The recovery runner created several local physics scenes but detached only the latest runtime. It now tracks and disposes each genre-owned scene before world teardown. The final player exited cleanly **5/5** with all observations passing. This is a real teardown defect, not a test-result-only failure.
6. The file checkpoint adapter deleted the old path before moving its temporary file: a crash in that gap would destroy the previous checkpoint despite the documented atomic-replacement guarantee. Changed the existing-file publication to `File.Replace(temporary, path, null)` after flushing the temporary; first publication still uses `File.Move`. The full dotnet solution passed after this fix. The GC-027 player fault test exercises the in-memory store's publication latch, not an actual process crash inside `File.Replace`; a filesystem power-loss guarantee is **not** claimed from that test.
7. GC-017's archived boundary list and trace-format list were updated from eight to thirteen names while preserving the historical 29-case results as historical. The executed data-loss and outbox tables are in `HANDOFF.md` §15 and the four GC-027 evidence files; no expected digest or test value was changed to make a failing behavior appear green.
