# GameCore Protocol 1.0 — provisional generic-execution profile candidate (GC-012)

**Status of every executable claim in this document: `NotRun (pending orchestrator build host)`.** GC-012 was
authored on a host with no .NET SDK, no C# compiler, no Mono and no Unity, so the profile below records the exact
*configuration* the gate will run and the source revision it is pinned to — not a result. One non-Unity command did
run here and is reproducible on any host with Python 3: `python3 tools/w4_generic_profile_audit.py`, whose output is
committed beside this file. That is a static source scan and is not a build, import or test result.

This is a **candidate** record for provisional generic execution. It is not a final conformance freeze (GC-028/029)
and it claims no support for any product platform that was not built and run (GC-030).

## 2. What "provisional generic execution" is claimed to mean here

Exactly four things, each observed by `-probeW4Profile` in the built player (and by `GameCore.W4Profile.Tests` in
the Editor):

1. **Both families are mounted late, not at startup, in one process.** The probe asserts `registryAtStart=0`,
   mounts narrative and cards by key through their committed generated catalogs, and asserts `registryAfterAll=0`.
2. **Reachability comes from generated roots, not linker preservation.** Each family has a generated inactive plugin
   entry (04 §8 item 3, TEST-001): `ProbeCatalog.NarrativeFamilyEntryKey` →
   `new GameCore.Validation.Slices.NarrativeFamilyPluginEntry()` and `CardCatalog.CardFamilyEntryKey` →
   `new GameCore.Validation.Slices.CardFamilyPluginEntry()`. Each entry's constructor calls its family package's own
   registration surface (systems, readers, lanes, chapters, registered reducer and predicate), so the closure is a
   real reference and High stripping has a root. `Assets/link.xml` no longer carries `preserve="all"` for the
   narrative gameplay or rules assemblies.
3. **Both families' outputs match their Editor/world fixture outputs.** Each family runs twice — over the committed
   generated catalog and over the slice's hand-written generated-style fixture catalog — and the two runs are
   compared canonically:
   * **narrative**: `NarrativeScenarioTrace.TryCompare(facts.PipelineEntries())` against the *committed* canonical
     trace declaration (`artifacts/gc-010/narrative-trace.json`, regenerated by
     `NarrativeScenarioTrace.ExpectedDocument()`, digest `NarrativeScenarioTrace.ExpectedDocumentDigest()`), plus a
     key-by-key equality of the two runs' pipeline values;
   * **cards**: the two runs' canonical facts digests (`CardFacts.Describe()`) must be equal. GC-011 recorded that
     the card slice has no declared trace document comparable to the narrative one; this gate therefore compares the
     two runs against each other and records that asymmetry rather than inventing a declaration.
4. **No generic contract requires a genre-specific type.** Zero `kernel → gameplay/rules/validation/generated`
   assembly edges (37 assemblies), zero `noEngineReferences` violations, no duplicate kernel assembly, every loaded
   gameplay/rules assembly referencing the kernel. See `audit.md`.

Additionally, this profile records the correction of the two kernel gaps GC-011 handed to Wave 4, because a generic
profile that still had them would be recording a defect as a feature:

* **P-017/P-019 multi-supporter slot.** A binding row now carries a support set and the published storage carries
  one `CapabilitySupportRow` per supporter; an `Additive` slot's composed value reaches a live world with its full
  provenance. `CardAdditiveScenario` observes one `cards.set-bonus` row on Seat A with composed value 5 (the +2 and
  +3 providers), two support rows, two distinct providers and a support-value sum of 5, then retracts the nested
  provider and observes the surviving +2 with one support row (P-033).
* **P-042 expected domain version.** `CommandEnvelope.ExpectedDomainVersion` is no longer dead data: it is checked
  at admission against the route's declared `IDomainVersionAuthority`, refused as `StalePlan` before the owner's
  lane, and folded into the idempotency hash.
* **P-032 manifest-supported reset.** The reset permission is now expressible in a manifest: `StateSlotSpec` gained
  an additive constructor overload carrying `resetSupported` and its recorded reason, and
  `OwnershipSchedulePipeline.OptionsOf` reads them, so a slot becomes resettable because its content says so rather
  than because a caller passed a bespoke option value. The proposal half (`SlotChangeKind.Reset` plus its required
  reason) already existed and is reused unchanged.

## 3. Protocol compatibility report

For each normative requirement this profile touches, the compatibility question is whether the revision *changes*
the protocol's observable semantics or only *implements* them. 00 wins over 05, 05 over 09; the table records which
document each decision is anchored to.

| Requirement | Compatibility verdict | Rationale |
| --- | --- | --- |
| P-001 | Compatible, unchanged | No kernel assembly gains a genre dependency; the audit's forbidden-edge list is empty. |
| P-004 | Compatible, **strengthened** | `CapabilitySupport` adds no new identity: it reports the five components of the existing `ContributionKey` (`Provider`, `Rule`, target, capability, slot) re-expressed per row. |
| P-005 | Compatible, unchanged | Provider **activation generation** travels with each support record, so a remount invalidates a support row exactly as it invalidates the row itself. |
| P-006 | Compatible, unchanged | No new version domain: revisions and epochs keep their meaning, and a re-derived identical row remains a `NoChange`. |
| P-008 | Compatible, **strengthened** | Support sets are canonically ordered (descending priority, then ascending provider and rule id bytes) and de-duplicated, so two runs that derive the same assembly report the same set in the same order. |
| P-009 | Compatible, unchanged | Both generated catalogs add one `PluginFactory`-kind group; catalog validation, key derivation and fingerprinting are the existing mechanisms. No unregistered key becomes resolvable. |
| P-017 | Compatible, **gap closed** | The support set is now part of the row rather than only of the derivation model, which is what P-017's "set of IDs, not a boolean owned by the last plugin" requires at the published layer. |
| P-018 | Compatible, **strengthened** | Support order is the sub-order of P-018 that exists at the row layer; candidate precedence itself is unchanged and still decided by the planner. |
| P-019 | Compatible, **gap closed** | `Additive` now publishes the reducer's folded value with its supporters instead of the top-ranked candidate's raw value. A slot composing several *values* (reducer-less `Additive`, `Ordered`) is still refused explicitly (`DerivationProposalOutcome.MultiValueSlot`) rather than truncated — recorded as an open later capability, not silently accepted. |
| P-024 | Compatible, unchanged | A spawned target inherits the same composed value **and** support set, because `DerivedBindingRule` carries both. |
| P-028 | Compatible, unchanged | The plan hash covers semantics only; support sets are semantic inputs of the row they accompany. |
| P-033 | Compatible, **strengthened** | Retracting one provider removes exactly its own support rows and leaves a co-supporter's support and the recomposed value intact. |
| P-042 | Compatible, **gap closed** | The "expected domain version if needed" clause is enforced. The guard is versioned composition data keyed by the declared route; the kernel learns only "this target's version is N". |
| P-032 | Compatible, **gap closed** | The manifest could not previously declare reset support, so 00's "manifest-supported" condition was unreachable from content. `StateSlotSpec` gained an additive constructor overload and two properties; the existing 11-parameter signature, `SlotAuthorityOptions`, `SlotChangeKind.Reset` and both validators are unchanged. Additions only. |
| P-050 | Compatible, **strengthened** | The guard participates in the admission idempotency hash, so reusing a request key with a different expected version is an `IdempotencyConflict` rather than silently retrieving the other attempt's result. |
| P-055 | Compatible, unchanged | No protocol version change: only optional data (an optional guard, an additional registration group) is added. Nothing falls back silently, and `SupportedFeatureIds` is unchanged for both catalogs. |
| P-058 | Compatible, **changed configuration** | The stripping configuration changed (narrative `preserve="all"` removed). The claim is the same; the mechanism carrying it is now generation. |
| P-059 | Partial | Two of the three reference compositions (cards, narrative) run; the action composition and the cross-family composition are Wave 7 (GC-024) and remain open. |

No contract change in this revision removes or renames a public member, and no existing semantics changed: every
addition is optional-with-a-default (`TargetBindingRow.supports`/`rule`, `ProposedCapability.supporters`,
`CapabilityBinding.SupporterCount`, `IDomainVersionAuthority`, `WorldMessagePlane.BindDomainVersion`,
`CapabilitySupportRow`). `tools/check_contract_surface_parity.py` (the GC-002/GC-003 seam check) therefore reports
additions only, which is the outcome the contract rule allows.

## 4. Reproducing this profile

```sh
# the whole gate, including the IL2CPP build and all nine probe modes, PROBE_RUNS=5
UNITY=~/Unity/Hub/Editor/6000.0.75f1/Editor/Unity DOTNET=$HOME/.dotnet/dotnet tools/run_w4_profile_gate.sh

# the W4 profile probe alone, against an already-built player
PROBE_RUNS=5 tools/unity/run_w4_profile_probe.sh

# the host-side generic-profile audit (runs here)
python3 tools/w4_generic_profile_audit.py --out artifacts/gates/w4-generic-profile/generic-profile-audit.json

# the W4 profile EditMode assembly alone
"$UNITY" -batchmode -nographics -projectPath unity/GameCore.Validation \
  -runTests -testPlatform EditMode -testFilter GameCore.W4Profile.Tests \
  -testResults artifacts/gates/w4-generic-profile/unity/w4profile-editmode.xml \
  -logFile artifacts/gates/w4-generic-profile/unity/w4profile-editmode.log
```

Artifacts the gate writes: `artifacts/gates/w4-generic-profile/{trx,unity,toolchain,generic-profile-audit.json}`.
Only `profile.md`, `audit.md`, `inventory.md`, `inventory.json` and this document's revision are committed by GC-012.
