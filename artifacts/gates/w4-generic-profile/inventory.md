## What this artifact is

A complete inventory of the GameCore V1 required surface: all 60 normative requirements `P-001`..`P-060`
(`docs/game-core/00-core-protocols.md`) and all 26 catalogued operations `O-01`..`O-26` (§10 of the same
document, with required suites and distinguishing probes from the `Operation-to-suite coverage` table in
`docs/game-core/08-validation-and-performance.md`). Owner tasks come from `docs/game-core/traceability.json`
(cross-checked against the `### GC-0NN` sections of `docs/game-core/09-implementation-guide.md`; no disagreement).

## Execution status of this artifact

**Every executable result of this artifact is `NotRun (pending orchestrator build host)`.** Nothing in this
change set was compiled, imported or executed: this host has no .NET SDK, no C# compiler, no Mono and no Unity.
The only work performed here was reading repository documents and archived artifacts and writing these two files.

The `Implemented+Evidenced` rows below do **not** rest on anything executed here. Each one cites an archived
executable artifact produced on the Linux build host by an earlier task or wave gate. This artifact claims only
that those files exist and say what is summarised here; it re-ran none of them and asserts no new pass.
No row is marked `Implemented+Evidenced` on the strength of a document whose own status line says
`NotRun (pending orchestrator build host)`; those `HANDOFF.md` files are deliberately not used as evidence.

## How a status was assigned

`status` is exactly one of three strings, and every row uses one of them. Quoted rules (GC-012 brief):

> - Status vocabulary is EXACTLY these four strings: `Implemented+Evidenced`, `Partial`, `Not yet`,
>   `Evidenced-Elsewhere` is NOT allowed — use only the first three.
>   - `Implemented+Evidenced` = an implementation exists AND an archived executable artifact on the Linux build host
>     exists for it (look in `artifacts/*/BUILD_REPORT.md`, `artifacts/*/HANDOFF.md`, `artifacts/*/toolchain/*.json`,
>     `artifacts/*/unity/*.xml`, `artifacts/*/trx/`).
>   - `Partial` = implemented or partly implemented, but the evidence does not cover the whole requirement, or the
>     archived evidence is from an earlier wave only.
>   - `Not yet` = no implementation/evidence yet.
> - O-01..O-26 are only `Implemented+Evidenced` if BOTH an implementation exists in `Packages/` and an archived
>   executable artifact on the build host covers that operation's distinguishing probe. Reviewers will check that you
>   did not over-claim. When unsure between `Partial` and `Not yet`, prefer `Partial` only if some code path exists;
>   otherwise `Not yet`.
> - Requirements that are semantic/kernel-wide (e.g. P-001, P-057, P-059) are `Partial` until their owning later
>   tasks (waves 5-9) close them; say which.
> - Never mark anything `Implemented+Evidenced` on the strength of a document that itself says the result is
>   `NotRun (pending orchestrator build host)`.

How the rules were applied here:

1. **Evidence is the current wave-3 integration revision.** `artifacts/w3-gate/` holds the newest full build-host run
   on one revision (655/655 .NET across 11 projects, 602/602 Unity EditMode across 12 assemblies, 6/6 PlayMode, a
   StandaloneLinux64 IL2CPP High-stripping player, and eight player probe families at five runs each). Because that
   gate re-runs every earlier wave's suite on the integrated revision, a wave-0..2 mechanism counts as evidenced when
   its test is in the w3-gate TRX/XML set; per-task artifacts (`artifacts/gc-0NN/**`) are cited only where the wave-3
   run does not carry the case (for example the GC-001 qualification profile in `artifacts/toolchain/`).
2. **Requirements.** A `P` row is `Implemented+Evidenced` only when the mechanism exists in `Packages/` **and** the
   archived wave-3 artifact set directly exercises the requirement's own normative content with no named sub-clause
   left unexercised. If any sub-clause maps to a later wave's named mechanism (checkpointing, adapters, retention
   under limits, replay, measured budgets, the action family, cross-family composition), the row is `Partial` and the
   `gap` names that sub-clause. Only `P-053` is `Not yet`, because no checkpoint code exists anywhere in the tree.
3. **Operations.** An `O` row is `Implemented+Evidenced` only when a handler exists in `Packages/` **and** the
   archived artifacts cover the operation's *distinguishing probe* from the `Operation-to-suite coverage` table —
   not merely its happy path. `O-20`..`O-22` are `Not yet`: `grep` over `Packages/` finds no `Checkpoint`,
   `RestoreCheckpoint` or `RecoverWorld` code path, and no `Checkpoint`/`Restore`/`Recover` test name exists in any
   archived TRX or XML. `O-24` is `Partial` because a code path exists (the callback gate) but the host side of the
   operation does not.
4. **`ownerTasks`.** For requirements, the tasks in `traceability.json` whose `requirements[]` carry the id. For
   operations, the union of the tasks owning the required suites listed for that operation, mapped through
   `tasks[].tests[]`. Both sets are listed in wave order.
5. **`nextOwner`.** The lowest-wave task in `ownerTasks` whose contract covers the missing mechanism named in `gap`
   (ties broken by wave); it is always a task in `ownerTasks`. Where the closing mechanism belongs to a task outside
   `ownerTasks`, the `gap` sentence names that task explicitly (for example `P-050`'s restore reservation is
   `GC-018`'s work while the row's `nextOwner` is `GC-014`). Kernel-wide rows (`P-001`, `P-057`, `P-059`, `P-060`)
   name the later-wave task that closes them.
6. **Every evidence path was checked to exist.** The 31 distinct evidence paths in `inventory.json` were verified
   with a shell `test -e` loop over the repository root: 31 checked, 0 missing. No `HANDOFF.md` is cited as
   evidence, because every `artifacts/**/HANDOFF.md` in this tree carries the line
   `NotRun (pending orchestrator build host)` for its own change set.

## Deliberate non-claims

Things that looked markable as done, and why they are not:

1. **`P-051` operation discipline.** Marked `Implemented+Evidenced` only for its normative obligations on the
   implementation — one control lane, immediate handles with terminal results, pure/cancellable status queries, a
   serialized cutoff race — evidenced by the wave-3 TRX/EditMode suites and the passing documentation validator
   (`artifacts/w3-gate/validator.log`). This is explicitly **not** a claim that §10's complete operation set is
   implemented: `O-20`..`O-22` are `Not yet` in their own rows.
2. **`P-060` evidence and release status.** The repository does record exact Unity/package/native-compiler
   versions, catalog hashes, commands, logs and fixture hashes, which tempts a "done" verdict. It stays `Partial`
   because the provisional budgets are unmeasured and failures/unload, checkpoint recovery and the
   no-per-frame-traversal counter evidence are outstanding (`GC-026`).
3. **`P-023` incrementality.** `GC-006`'s archived run shows runtime derivation equals the full-recompute oracle for
   50 seeds x 40 operations. That is not TEST-008's 50 seeds x 500 operations, and the "local changes do not rescan
   untouched sibling scopes" index counters are `GC-013`'s, so the row is `Partial`.
4. **`P-008` / `O-14` determinism and advance.** Idle worlds at 8, 60 and 600 frames with zero steps are archived,
   and fixed-step debt is archived. The 10,000-step replay with shuffled producer/completion order at 1, 2 and 4
   workers is not, so both rows are `Partial` rather than inheriting the idle evidence.
5. **`P-007` per-assembly service resolution.** Integration tests and probes exercise bindings, but "resolve once
   per assembly, not per target per frame" and the zero-string-lookup/zero-tree-traversal counters require TEST-023
   on a standalone player, which has not run. `Partial`.
6. **`O-18` cancellation idempotency.** `GC-004` recorded a real, reproduced blocker: reusing one cancellation id
   against different targets returned `Cancelled` twice and lost the original attempt. That text is historical —

   `CancellationRequestAtAnAlreadyUsedIssuerSequenceIsRejected` — so `O-18` is `Implemented+Evidenced`, while the
   still-missing caller-reserved session reservation keeps `P-050` at `Partial`.
7. **`O-26` pause.** Status-only pause, no paused-time debt, retained debt on resume and an unchanged step/epoch are
   all archived. The probe clause "pause waits for the boundary" is not: no archived run pauses while a tracked job
   is executing (the implementation relies on the main-thread requirement rather than an observed wait). `Partial`.
8. **`O-24` async completion.** The callback gate rejects foreign-world and stale-activation tokens and releases
   only their own acquisitions, which looks like the whole operation. It is not: no host path accepts a stamped
   completion into staged state or turns an active gameplay completion into a typed command, and there is no
   duplicate-completion lease rule test. `Partial`.

## How a status was assigned

- `Implemented+Evidenced` — an implementation exists **and** an archived executable artifact on the Linux build
  host covers it (found in `artifacts/*/BUILD_REPORT.md`, `artifacts/*/toolchain/*.json`, `artifacts/*/unity/*.xml`
  or `artifacts/*/trx/`).
- `Partial` — implemented or partly implemented, but the evidence does not cover the whole requirement, or the
  archived evidence is from an earlier wave and no longer matches the current revision.
- `Not yet` — no implementation and no evidence.

Never `Implemented+Evidenced` on the strength of a document that itself says `NotRun (pending orchestrator build
host)`. Remaining V1 capabilities stay open tasks and never become optional.
