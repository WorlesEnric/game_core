## Fixes and reasons

1. **Compile/API mismatches:** renamed the `DerivationChangeSet` helper colliding with its property; corrected `CapabilityImport` fixtures and `ProviderContributionIndex`'s provider-ID wrapper; changed the install-path cache field to a mutable dictionary; ordered dirty `TargetId`s by underlying ID; corrected `ServiceConsumerIndex`'s `Id128` keys; hashed `FactoryKey.KeyVersion` without narrowing unsigned versions; imported `System.Collections.Generic` in two test files and `GameCore.Derivation` in the card Unity host. Unity NUnit's `Does.Not.Contain(ScopeId)` overload resolved to string: replaced four assertions with equivalent typed `Has.None.EqualTo` assertions. No acceptance assertion deleted.
2. **Exact oracle parity:** the oracle lacked the target population filter and emitted decisions for targets that advertised neither selector schema nor output capability. Added the same predicate used by runtime targeting. The incremental engine incorrectly reclassified carried decisions against only the dirty-target accepted map, confused an empty *valid* explanation set with missing provenance, and repeated a target per installation when installations shared a rule ID. Reclassified fresh decisions only, accepted empty explanations with zero decisions, and deduplicated per-rule dirty targets. Added the missing `rule-keys` reason to change reports. Both full 50×500 sweeps now pass decisions, provenance and canonical state.
3. **Invalid composition fixture:** the import test named a provider that had never been mounted; production correctly refused it. The fixture now registers/mounts a real provider before granting, and asserts staging; original scope-fact assertions remain.
4. **Mode retraction/publication:** a complete derivation proposal can legitimately contain zero supported slots in Conservative mode; rejecting it as `NoAssemblies` left old rows and incorrectly reported `NoTargetChange`. Such proposals now identify complete support; the planner retracts rows no longer declared and retires the corresponding rules, while partial mount/unmount proposals retain their old semantics. The publisher clears the adopted-publication marker on `NoChange`, allowing the next unchanged-assembly/spawn publication for that pair. These fixes preserve the prior epoch on refusal and make both switch directions publish normally.
5. **Unity scenario fixtures:** card scopes now enter the initial lane seed instead of eight post-join edits (initial epoch stays First); narrative eligible dialogue targets now name the two villager recipes rather than unrelated gate/encounter recipes. The isolated-branch observation still requires unchanged effective fingerprint, zero rows, no binding and zero emitted decisions. A newly introduced provider behind an isolation boundary legitimately creates a `BlockedByBoundary` *decision*, so that target can be dirty for provenance without changing its effective assembly. Skipping it in the invalidation closure broke the full-recompute oracle and was reverted; only the invalid dirty-set-membership assertion was corrected. Observation names and digest literals did not change.
