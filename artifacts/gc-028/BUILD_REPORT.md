## Fixes and rationale

1. `CompositionHost` nullable lifecycle report and `InstallationLifecycleCoordinator` local-name collision: two actual C# compiler errors in the uncompiled P-012 addition; preserve nullable report contract and rename local.
2. `LifecycleController`: import `GameCore.Unity.Runtime.Faults` for the guarded P-012 fault latch types; Unity compilation otherwise fails despite the pure solution compiling.
3. `CompositionHost.FailActiveProvider`: a repeat against an already Failed installation is lane `NoChange`, not a refusal; return the committed deactivated token without advancing revision/epoch. The refusing-validator test fixture now permits setup mounts and refuses only the targeted provider-failure publication. The P-012 refusal and closure assertions were not weakened.
4. P-052 diagnostic closure tests: `None` has printable text but `TryParse` resolves only the required `Values` list and correctly rejects `None`; `ProviderFailed` is an additive P-012 code. Mirrored that additive enum member/text/list to the frozen seam and regenerated its API snapshot with `dotnet run --project dotnet/tools/GameCore.ApiSnapshot -c Release -- --assembly dotnet/src/GameCore.ReferenceSeams/bin/Release/netstandard2.1/GameCore.ReferenceSeams.dll --output tests/GameCore.ReferenceSeams/api/GameCore.Contracts.api.txt --namespace GameCore.Contracts`.
5. Recovery fixture's fault-boundary vocabulary was stale after the new `provider-deactivation-publication` latch; added the fourteenth name in enum order and adjusted its count/union assertions and explanatory prose. Earlier W5/recovery tests now execute against the new table.
6. `run_test_matrix.sh` had two malformed `run_catalog_coverage_probe.sh` arguments (`CatalogCoverage` is a mode selector for the summarizer, not an argument the harness accepts) and omitted four harness modes used by normative evidence references; corrected mappings without deleting any TEST row. `evidence_map.py` budget decision path pointed to the wrong relative parent; fixed to the actual recorded decision document. Wrote the genre-audit check output into the current evidence root as its map declares.
7. The marker-free release clone accidentally retained P-012's qualification-only `ProviderFailureScenario`, which references stripped fault fixtures and fails compilation. Removed it in the clone preparer and named it in the clone source-surface checker; the shipping runtime and kept probes remain intact.

The new `ProviderFailed=22` is an additive documented API change, not a change to P-052's twenty required codes. The only changed test expectations reflect production/frozen-seam parsing semantics and the new fourteenth fault boundary; no tests were skipped, ignored, deleted, or loosened. The P-037/P-047 normative clarification shipped on the branch and the full documentation validator passed. No unqualified platform is claimed.
