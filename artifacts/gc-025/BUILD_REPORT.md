### Generated-root masking check and falsifiable negative

Source inspection: `CatalogCoverageScenario` calls generated `TryGet*` APIs with manifest/derived keys (and coverage-companion `ExerciseRegistrations`, `ExerciseSchemas`, `ExerciseClosedGenericRoots`); `CatalogCoverageProbe` dispatches the scenario. The probe does not construct concrete card plugin implementations or use `typeof`, reflection, `Activator`, or direct serializer/concrete-type references to accidentally keep them alive. Generated catalog registration arrays contain the direct constructor roots; generated companions exercise those arrays and generated serializers. A separate hand-written traversal fixture does reference some traversal concrete types, so it would be misleading to say **all** traversal concrete types are rooted exclusively by generated code. The falsifiable entry chosen was the card plugin factory.

Copied the marker-free release project to disposable `unity/GameCore.NegativeCheck`, removed **only** the `CardTablePluginFactory(CardTablePluginKey)` bound registration from its generated `CardCatalog.g.cs`, built a fresh IL2CPP/High/Burst scratch player with guarded `tools/unity/build_probe.sh`, then invoked its `-probeCatalogCoverage` under `timeout 600`. Expected **Fail**, exit **1**: `artifacts/gc-025/negative/result.json` reports `cards/cards.factory.card-table-plugin: the generated lookup returned no implementation for PluginRegistrations`, exercised registrations **7/8**, and `cardTablePluginFactory=missing`. The catalog metadata still fingerprinted the same; the runtime lookup, not a file-hash-only check, exposed the absent root. Scratch clone was removed; production files were not modified.

## Fixes, failures, and limits

1. `CatalogCoverageScenario.cs`: `ImmutableCatalog` has no `RegistrationGroupCount` property (initial Unity import `CS1061`). Report the generated `TraversalCatalog.RegistrationGroupCount` constant instead; passing Unity tests and player prove the fix.
2. `BakeCatalogCoverageAuthoring.cs`: `int[] != new int[]` checks object identity and rejected a valid authored `{1000,0,0}` velocity. Compare length and three components instead. Failed initial Editor bake and successful regeneration retained.
3. `tools/run_gc025_gate.sh`: TRX `LogFileName` overwrote previous solution-project test files. `LogFilePrefix` retains all 14 result files; second actual full .NET test run passed.
4. Host scheduling: guarding each Unity/player invocation avoids contention with GC-026's benchmark. First post-fix resolve showed **no log progress for 10 minutes**, after `Unloading 75 Unused Serialized files`; `gdb -p` was denied by ptrace policy, `sudo -n gdb -p 647610 -batch -ex 'thread apply all bt'` captured main thread waiting in `GarbageCollectSharedAssets` / `UnloadUnusedAssetsOperation::IntegrateMainThread` / `EditorSceneManager::FinishNewScene` and worker threads waiting on the dynamic loader TLS mutex. Canceled the hung invocation and retried once; the same revision resolved successfully. The hang remains **intermittent and not source-fixed**; every further Unity run retained its watchdog. It was not silently polled past 10 minutes.
5. `tools/check_release_clone.py`: previously walked generated `Library`/`Builds` files (7,060 paths on a built clone, timeout) and rejected any lock file, even one generated by Unity after resolving a valid marker-free clone. Scan source/config only and validate an optional resolved lock contains no qualification/replay dependencies. Unbuilt and built release clone checks now pass.
6. `artifacts/baseline/ENVIRONMENT.md`: populated actual toolchain, package and native player hashes; corrected earlier template's `no lock` release wording. The resolved marker-free lock has zero qualification/replay dependencies.

The project has no `Baker<T>` or authoring prefab pipeline. The player verifies definition/layout/descriptor/applier/fingerprint/run parity; a prefab-bake claim would require a new pipeline. Existing GC-020/W6 `generatedCatalog=absent` assertions describe their own single hand-written-catalog run; this task proves the newly generated catalog separately, so their frozen digest/assertions were not changed.
