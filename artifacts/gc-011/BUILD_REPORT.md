## Fixes and why

1. **Unity compile blockers:** restored the card-rules namespace imports in gameplay declarations/registration, corrected the three `Manifest` argument lists, used the `FactoryKey.RegistrationKey` for field identity, restored required `Unity.Collections` asmdef references, and passed `SlotMigrationRegistry` to the ownership validator rather than the planner's different `MigrationRegistry`. Removed a call to a nonexistent automatic-propagation method (the existing mount observation executes those assertions). Unity imported successfully afterward.
2. **Ownership and scope tree:** declared field ownership against the actual slot/domain schema, as `OwnershipSchedulePipeline` constructs physical layouts from `StateSlotSpec.Schema`; otherwise compilation rejected all five domains. `ScopeRegistry` now constructs nested scopes parent-first by depth before canonical ID sorting; a child ID below its parent previously made the constructor throw despite a valid parent. Added `NestedScopesSurviveCanonicalIdentityOrdering` as a regression; it fails the former constructor and passes the fixed one.
3. **One publication series:** a no-target-change composition edit still requires a corresponding published world image before another edit can be adopted. Added `AssemblyPublisher.PublishUnchangedAssembly` for a validated no-change derivation, and used it when the scenario creates scopes and mounts the table/rule library. Kept `DerivedAssemblyPipeline.PublishDerived`'s no-target-change behavior unchanged so the existing W2 spawn can still consume its pending publication. The scenario seeds after its scopes exist, then reads live target/seat counts; its rule-library unmount returns `NoTargetChange` as a valid precursor to the spawn publication. This was a generic publication gap exposed by GC-011, not a card-only fallback.
4. **Actual derivation eligibility at planner boundary:** `DerivedCompositionProposal` now tags each proposed capability with the specific derived target identity; `AssemblyPlanner` filters those candidates by target as well as recipe. Previously it broadcast a bonus for League B to every seat sharing the recipe, including League A and the isolated practice seat, overriding their correct derived values. Direct planner declarations without target IDs preserve their original recipe-wide behavior. The integration run now observes existing seat bonuses 2/2/1, isolated practice 0, and future seat 2.
5. **Batch fixture's invalid expectation:** `07-reference-compositions.md` §2.3 orders candidates by `(TurnNumber, SeatOrdinal, IssuerSequence, CommandId)`; with the same turn, seat ordinal precedes sequence. The original fixture expected seat C (ordinal 2) to beat seat B (ordinal 1) just because C bid with sequence 3 against 7. Changed the input order and sequences so seat B wins despite bidding after C; the expected winner changed accordingly, matching both the design and `CardSetRules.IsEarlier`, without weakening conservation checks. The holder loses one, only the winner gains one, and the version advances once.
6. Unity-generated `.meta` files and `packages-lock.json` are committed. The generated probe catalog was regenerated by `build_probe.sh`; the committed card catalog's fresh-generation, fingerprint, verification, and key-derivation tests were among the 44 passing compiler tests.
