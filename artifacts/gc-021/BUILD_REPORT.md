## Fixes and decisions

1. `DurableOutbox.DeliveryCursor` lacked the stored `DestinationId`; delivery key derivation referenced a nonexistent public `Id128Codec.ReadUInt64BigEndian` and wrote an eight-byte length into a four-byte label prefix. Added the cursor field, used `ReadBigEndian` and wrote exactly four big-endian prefix bytes. This fixes compilation and prevents digest input overlap.
2. Fixed the outbox codec sample's `OrderOrdinal` type (`uint`), the destination test port's public interface properties, and typed row-kind fixture. Checkpoint fixture now declares both scopes when it declares both targets; the API-snapshot allowlist records new public outbox types. The roundtrip order assertion changed from 13 to 8 because the codec sample now correctly writes field 22 as 8, not a mispositioned 64-bit value. These are test fixture corrections, not weakened assertions: the schema declares field 22 as `uint`.
3. Unity compilation required removing an instance `ToString()` override from static `CardTableConstants` and adding missing message-plane, card-rule and fixture namespace imports. No gameplay semantics changed.
4. GC-021 world scenario originally submitted its checkpoint fixture's queued narrative choice to a live conversation seeded at a different node; it emitted no committed choice. It now submits `Gc021Choice.Of(family)` for the narrative world. Restored delivery explicitly acknowledges an `Applied` result; `TryDeliver` correctly leaves that result open pending acknowledgement. The reward destination now uses the bridge's dedicated issuer rather than reusing a family's already-advanced issuer sequence, which had caused `ResultExpired` and no card transfer. The card family's transfer now grows the receiving hand from 3 to 4; the narrative world observes its committed choice and records a durable obligation, but has no card table installed, so its destination remains explicitly unavailable, not falsely counted as a card grant.
5. `DurableDeliveryAdapter.TryDeliver` previously returned a settlement success code (`None`) rather than the destination's explicit rejection/compensation reason. It now propagates the destination code. More importantly, it previously settled rejection/compensation directly in the in-memory outbox, bypassing the adapter's persist-before-settle methods; it now uses `TryReject`/`TryCompensate`, retaining terminal outcomes across recovery. The latter fix was made after reviewing the passing probe and all affected suites/player builds were rerun.
6. The probe shell validator read nonexistent JSON `steps` instead of actual `probes`; fixed. Both digest literals were measured from real passing IL2CPP runs, committed, rebuilt and asserted for five fresh runs.

Design limitation retained, not called a pass for an unrun behavior: the narrative fixture and card fixture are separate worlds. The narrative half verifies the committed choice produces one durable reward obligation but cannot apply a card command without a card table; the card half verifies one committed transfer through its own command port and preserves that world's unrelated state through the scenario. A single actual world mounting both families and delivering that *same* narrative receipt into its card table is **NotRun**; thus the stronger combined-world narrative-to-card acceptance must not be inferred from these two demonstrations. The checkpoint probe captures/plans the outbox and cursor and tests reinstate separately; its detail states `executorRestore=not-run` for this scenario (GC-018 executor tests are separate). No universal gameplay Effect API was added. Full TEST-015 1,000-cycle teardown belongs to GC-022 and was not run as a GC-021-specific acceptance claim.
