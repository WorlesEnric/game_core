# Staging lane (P2.4)

Code and mechanisms generated by agents are staged and validated in an isolated Unity project before they can
affect the live editor. Nothing a worker produces loads into the active Editor until two things have happened: a
**passing StageVerdict** exists for exactly its artifacts, and the creator has given an explicit **Admit**.
Unrestricted script execution is never the editing mechanism.

```
mechanism.propose candidate ──POST /v1/stage──▶ slot (isolated project) ──7 steps──▶ StageVerdict (artifact)
        │                                                                              │
        └──────────── creator: Admit ──▶ StageAdmission (Editor) ◀── verdict sha match ┘
                                          copy package → recompile → checkers → re-bake →
                                          live catalog hash == predicted → Applied   (else rollback)
```

## Steps

1. `scan`: the forbidden-content scan (`forbidden-rules.md`).
2. `checkers`: `slot-checks.py`.
3. `dotnet`: `dotnet build` and `dotnet test` of the Unity-free rules half. It is skipped with
   `facts.notApplicable` when the package has none.
4. `unity-editmode`: batchmode compile plus EditMode tests. These are the package's own tests and the harness
   `CatalogProbe`, which writes the `catalogDelta`.
5. `playmode-smoke`: the harness boots a tiny world with the mechanism mounted and runs the proposal's
   `smokeTest` entry for N frames. It asserts one sanctioned pump per frame and no exception.
6. `determinism`: the smoke test runs twice on fresh worlds, and the two canonical slot hashes must be equal.
7. `budget`: the whole stage must finish within B-STAGE = 6 min (`GAMECORE_STAGE_BUDGET_S`), otherwise
   `failure: "timeout"` (`stage_failed{timeout}`).

When `scan` or `checkers` fails, every later step that would run code is skipped. Unity runs through
`studio/tools/unity-batch.sh`: the host-wide lock in `~/wkspace/gc-studio/.unity-slots` (at most 3 Editors
host-wide), one Editor per stage, a 600 s silence watchdog, and one retry on the known package-resolve hang.
Children start with `env_clear()` and receive only the allowlist (`env.rs`), which never includes anything whose
name contains KEY, TOKEN, SECRET, PASSWORD, CREDENTIAL, AUTH, COOKIE, SESSION or PRIVATE. Every log is redacted
before it is written. A step's `logRef` is the sha256 of its redacted log.

## Verdict (`gamecore.studio.stage-verdict/1`)

The verdict is canonical JSON, and its sha256 is the verdict id (`verdictRef`). The companion keeps it in its
artifact store, and the slot keeps a copy at `out/verdict.json`. Fields:

- `changeSetId`, `slot`, `package`
- `steps[] {id, status: pass|fail|skipped, durationMs, logRef?, detail, facts?}`
- `pass`: every one of the seven steps passes or is not applicable, there are no forbidden hits, no failure, and
  the run is not partial (a partial run comes from a `steps` subset).
- `artifacts[] {role: package|proposal, sha256}`: what the verdict covers.
- `files[] {path, sha256, bytes}`: the staged package, file by file.
- `catalogDelta {world, mechanisms[{package, catalogType, fingerprint}], predicted}`. `predicted` is
  `sha256("gamecore.catalog-set/1\n" + world + "\n" + join("\n", sorted mechanism fingerprints))`.
- `forbiddenHits[] {rule, path, line, excerpt}`, `failure?`, `runner`, `durationMs`, `budgetMs`, `createdAt`.

## Running

From a shell on the build host:

```
gamecore-studio stage run <slot> --candidate DIR [--source-project games/hollowmere] [--steps a,b] [--verdict-out F]
gamecore-studio stage run <slot> --package-dir DIR --change-set-id cs_...      # legacy shape
gamecore-studio stage gc [--max-age-days 7] | discard <slot> | scan <package-dir>
```

The `run` command exits 0 on pass, 1 on fail and 2 when no verdict could be produced. The last stdout line is the
verdict JSON.

Through the companion (`docs/studio/04`):

- `POST /v1/stage {changeSetId, slot?, steps?, sourceProject?}` returns 202 with the job
  `{jobId, changeSetId, packageRef, state, slot}`. The candidate must already be in the ledger as a validated
  candidate carrying `mechanism.propose`.
- `GET /v1/stage/{job}`: `state` goes `queued → running → done|failed`. `verdict` is the StageVerdict plus
  `verdictRef`, or `{code: stage_failed, reason, message, hint}`. Each transition is also sent as a `stage` event on
  `/v1/events`.
- `POST /v1/stage {changeSetId, action: "discard"}` removes the change set's slot (on Reject).
- The old `{changeSetId, packageRef}` request still runs `stage.sh`.

Slot rules:

- One stage per slot: a second request returns `409 ledger_conflict`, because `.stage.lock` is held.
- One slot per change set, and one change set per slot.
- A slot is garbage-collected 7 days after its last verdict, or when the change set is discarded.

The slot root is `GAMECORE_STAGE_ROOT`, defaulting to `~/.cache/gamecore-studio/stage`. A first stage imports the
whole project. After a successful EditMode run the runner seeds `_warm/Library`, and later slots start from it.

## Admission (Unity, `StageAdmission`)

`StageAdmission.Of(runtime).Admit(candidate, verdictBytes?, captureAndStop)` runs these steps:

1. Play Mode must be stopped. With `captureAndStop`, the game is first captured to save slot `admit-<id>` through
   `AdmissionOptions.Capture` and then stopped. The game registers `SaveServiceAdmissionCapture`, the P1.2
   SaveService checkpoint.
2. The candidate's `mechanism.propose` becomes `mechanism.admit`, keeping the same change-set id and artifacts and
   adding the verdict artifact. Its validator `RequiresStageVerdict` refuses the operation unless the verdict:
   - passes,
   - names this change set,
   - covers exactly the package and proposal digests,
   - lists every file the archive holds with equal sha256.

   Refusal reasons are `verdict_missing`, `verdict_failed` and `artifact_mismatch`.
3. The engine applies the change set (journal Interrupted, checkpoint, Applied), writing the package from the
   retained archive into `<project>/Packages/<name>`. With the shared policy it goes to `<repo>/Packages/<name>`
   with a manifest entry. The entry is then held Interrupted with `stage.admission` pending, a pending record is
   written to `Library/GameCoreStudio/stage/`, and the project recompiles. The compile waits until the Package
   Manager has registered the changed package list, so `versionDefines` follow it.
4. A compile error, a failing checker run (`slot-checks.py --package-dir`), a failing re-bake (`Entry.Verify`), a
   missing mechanism catalog, or a live catalog-set hash that differs from `catalogDelta.predicted` each roll the
   admission back. The rollback runs `RollbackInterrupted` (the `mechanism.remove` inverse deletes the package),
   writes `stage.admission` fail, recompiles, and offers the capture slot for restore.
5. Otherwise the entry becomes Applied with `stage.admission` pass. After a domain reload, `AdmissionResumer`
   continues steps 4 and 5 once the Editor has been idle for a few seconds. A refused re-bake is retried 3 times
   at 10 s intervals before the admission rolls back.

`Undo(id)` journal-undoes the admission (the package is removed), recompiles, and checks that the live catalog
hash has returned to its value before the admission (`stage.undo`).

The journal's `validation` carries `stage.verdict` (pending/pass/fail, with the verdict id and slot),
`stage.admission` and `stage.undo`. P2.1 shows "verdict pending/pass/fail" from `stage.verdict`.

For batchmode, used by `w-mech-01.sh`:
`-executeMethod GameCore.Studio.Edit.StageCommandLine.Admit -gcCandidate DIR -gcVerdict FILE -gcResult FILE`
and `...StageCommandLine.Undo -gcChangeSet cs_... -gcResult FILE`.
