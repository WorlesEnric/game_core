## 1. What was built

`gamecore-studio` is a Rust process that etosd supervises as an installed agent. It bridges the Unity editor (through the node's proxy) to etos tasks, files, topics, ops, realtime and the Resource Graph. It follows docs/studio/02 (boundary D, SADR-002/003/005/018/020) and 04.

| Area | Where | What it does |
|---|---|---|
| Lifecycle | `src/app.rs`, `src/main.rs` | Startup order: ledger, then a loopback HTTP listener (port from `config.port`, else `$ETOS_STATE_DIR/port`, else ephemeral; the result is saved), then `Agent::connect_with`, then the minimal `status` service, then `PUT /agent/endpoint`. A 500 ms monitor PUTs the endpoint again after each reconnect **and whenever the welcome's proxy token changes**; a failed PUT is retried on the next tick. Shutdown is graceful on SIGTERM/SIGINT. |
| Proxy checks | `src/api.rs::authenticate` | `X-Etos-Proxy-Token` is checked against the **current** welcome token (the SDK re-registers on reconnect and drops the returned token). A mismatch gets 403 `forbidden`. `X-Etos-App` must be in `allowed_apps` (default `gamecore-unity`), else 403. Before the first welcome the answer is 503 `agent_starting`. |
| Unity API | `src/api.rs`, `src/model.rs` | 04 §2 (see §4 below). JSON is camelCase serde mirrors of 03. **Null policy (03 §9):** every answer, event, voice frame and stored outcome is written with optional members omitted, never `null`; every request body containing a `null` is refused (400 `bad_request`, message `null at /pointer`). Errors are `{code, message, hint, diagnostics?}`; etos refusals pass through unchanged (status, code, message, hint). Framework rejections (413 body limit, 400 bad JSON/query, 405, failed upgrade, unknown route) are rewritten into the same shape by a response layer. Companion codes are those registered in 04 §2. Requests, candidates and cancel are **scoped to the calling app** (`X-Etos-App`); another app's request is 404. |
| Ledger | `src/ledger.rs` | SQLite (WAL, `synchronous=FULL`). Tables: requests, attempts, candidates, artifacts, events, voice sessions, stage jobs, tool catalogs. Requests are idempotent by `changeSetId`: the same body returns the stored request, a different body gets 409 `ledger_conflict`. **Terminal states are final.** Startup resumes open requests and never reopens a task. |
| Task desk | `src/desk.rs`, `src/candidate.rs`, `src/schema.rs` | **Submit:** `selection` and `contextSlice` are validated against `selection-snapshot.schema.json` and `semantic-index.schema.json` (after stripping the `rgKind`/`rgKey` extensions); the catalog against `tool-catalog.schema.json`, and its digest must equal `toolCatalogRevision` (and its own `revision` when present). Findings answer 400 with `diagnostics`. **Open:** packs `request.md`, `selection.json`, `index-slice.json` (capped at 2 MiB, with a truncation note), `tool-catalog.json` and attachments; uploads them; opens the task with `id = changeSetId` on `#agent/gamecore-studio/cs-<lowercase ulid>` (`cs-01j9zq…`, re-ask `…-r1`). One open at a time per request (a per-request lock, and the attempt's packed inputs are written only while NULL, so the first writer wins). **Follow:** long-polls the topic. **Finish:** on the final record, fetches every ref, identifies documents by content, and checks no `null`, the JSON Schema, candidate mode, the structural rules, each artifact's sha256 and size against the delivered bytes, and the **catalog rules** (tool ∈ catalog, args known and required ones present, target present/kind/scope; a catalog that is not the request's revision is `StaleContext`). Record text and task errors are redacted before they are stored. Valid artifacts are stored content-addressed and a `candidate` event is emitted. **Cancel** goes through etos. `waiting` is surfaced and never retried. An invalid candidate gets **one** automatic re-ask (`<cs>.r1`, parent task recorded, `diagnostics.json` attached), then it is terminal; `StaleContext` is not re-asked. A re-ask etos refuses settles `candidate_invalid` with the original diagnostics plus a `Refused` diagnostic (`data: {code, status, hint}`). A `failed` closing record is checked against `GET /tasks/{id}` (a cancel there settles `cancelled`). The re-ask (attempt row + request pointer) and candidate acceptance (candidate row + state) are each one SQLite transaction, and nothing is recorded or emitted once the request is terminal. An `unresolved` request is followed again on at most 3 restarts or for 24 h, then given up (`outcome {code: unresolved, gaveUp: true, gaveUpReason}`). |
| Media ops | `src/ops.rs` | The SDK's typed calls: `Ops::generate("image" \| "3d")`, `Ops::tts`, `Ops::describe` (the `Ops::generate` workaround is gone; etos `278ef9c` fixed it). Each op has its own client timeout `ops_timeout_secs` (default 300 s) and holds the caller's request until the node answers. Past that it answers 504 `transport` with the op `key` in `hint` and `data.key`, and an identical resend reuses the key. `max_cost_usd` is **required** (or the configured `ops_max_cost_usd` default ceiling) and is passed with image, tts and 3d (not `describe`, whose etops input has no such field; a ceiling of 0 refuses `describe`); without a ceiling image/tts/3d are 400. The idempotency key is `gc-<sha40>` over changeSetId, op, spec and the ceiling. Outputs are fetched, checked against the node-reported `digest` when present (mismatch: 502 `protocol`, nothing stored), stored with the node's media type, indexed (`gc_asset`) and announced with an `asset` event. Hello reports each provider from the free `status` op (live / not_configured / blocked / unknown), cached 60 s. |
| Voice | `src/voice.rs` | Transcription only. `realtime().open("studio-voice", pcm16/24000)`. Client frames are at most 24 KiB raw (32 KiB base64); a larger frame is refused with an error frame `too_large` and not forwarded. Each frame is one etos `input_audio` with gapless `audio-<seq>`. Only `role == "user"` transcripts are forwarded, with `final: true` only on the item's done revision. It never sends `response_create`, and audio/response events are dropped. A refusal reaches the client as `{type:"error", code, message}` followed by `closed`. |
| Index logger | `src/index.rs` | Declares 10 global `gc_*` states under the agent's own binding. Rows are coalesced per (kind, key), and a ticker sends **≤1 batch/s**. Rows are flushed on shutdown. Removals become `removed: true`. Node `type` is the `[Authorable]` type id (`npc.definition`, `dialogue.graph`, …): the node shape is 03 §3, the attribute 03 §4. |
| Stage runner | `src/stage.rs` | Runs `studio/stage/stage.sh <slot> <package-dir>`: the package is extracted from the store, `env_clear` plus an allowlist is applied, and a timeout is enforced. The verdict is the last JSON line on stdout. A missing script gives 503 `stage_failed{hint}`. |
| Artifact store | `src/store.rs` | Content-addressed under `$ETOS_STATE_DIR/artifacts/sha256/<aa>/<hash>`. Written to a temp file with a random suffix (`create_new`), fsynced, re-hashed, renamed, then the directory is fsynced. |
| Logging | `src/redact.rs` | `tracing` to stderr through a redacting writer (removes `etk_/ett_/etp_/eta_` tokens and `Bearer …`). The environment is never logged. The stage child gets an allowlisted env with secret-like names removed. |
| Manifest | `studio/etos/agent/agent.toml` | `command = "bin/gamecore-studio"`. Grants: `logger, query, changes, tasks, files, topics, ops, providers, realtime, proxy, services`. `providers = ["studio-voice"]`. Workers `gc-designer` and `gc-mechanic` use `model = "default"`. |
| Workers | `studio/etos/agent/workers/*.md` | Per 04 §4: read the tool catalog first, produce only catalog ops, never invent ids, copy `selection.json`, write `/outputs/changeset.json` (with the P0.3 schema fields only) with an artifacts sha256 list, ask at most one clarification question via `/outputs/clarification.json`, never claim unwritten assets, never write `null`, no candidate-mode fields, and the catalog rules the companion checks (`tool` is a catalog `id`, required args, target kind/scope). The mechanic's `mechanism.propose` must itself be in the catalog. The mechanic also uses the 03 §8 package layout, runs `dotnet test` first, and writes `proposal.json`, `package.tgz` and a `mechanism.propose` change set. |

### P0.1 host-run follow-ups (applied)

From `docs/studio/packets/P0.1-host-etos.md` §3–§4 and `artifacts/studio/environment/etos-verify-2026-10-04/DIAGNOSIS.md`:

1. **Task-open timeout.** etos launches the task inside `POST /tasks` (`crates/etnode/src/task.rs` `create` → `advance_now` → `launch`), and the SDK's default 30 s timeout dropped that request under host load, leaving the task `starting`. Two things dropped it in the companion, and both are fixed:
   - `POST /tasks` now goes through its own client: `task_open_timeout_secs` (default **180**, `config.toml`) and **no SDK retries**.
   - `POST /v1/requests` used to wrap the open in a 30 s `tokio::time::timeout`, so answering the HTTP call dropped the in-flight `POST /tasks` itself. The open now runs in a spawned task; the submit waits up to 30 s for it and then answers, and the open carries on. The follower takes the same per-request lock, so it cannot open a second time while the first is in flight.

   A timed-out open is **not** a failure: the request stays open with `taskStatus: "opening"`, and after 5 s the follower re-reads the task. **Deviation from the brief:** etos's `GET /tasks/{id}` takes only the node's task id (`crates/etagents/src/tasks.rs::get` looks up `api_agent_task.task`), which the companion never received. So the re-read is the idempotent `POST /tasks` with the same request id (`.../tasks.rs::open` returns the recorded task for a known request id). Once a task id is known, the follower reads `GET /tasks/{task}` as before.
   - **Caveat for P0.1:** etos records the request→task row only *after* `open_task` returns. If etos drops the handler mid-launch, the re-read opens a second task, and the first stays `starting`. With a 180 s timeout this needs a launch slower than 3 minutes. **Suggested etos patch:** insert the `api_agent_task` row before launching, or launch detached from the request.
   - Test `a_slow_task_open_is_reread_not_failed`: the fake node records the task and answers after 2.5 s, against a 1 s timeout. The request is not failed, ends up with that single task (≥2 `POST /tasks`, 1 task) and completes to `candidate`.
2. **`tests/real_node.rs` no longer passes on failure.** Each designer request must end `candidate` or `needs_clarification`. Any other end state (`failed` at `phase: open`, `task_failed`, a degraded model, `candidate_invalid`, `unresolved`) fails the test and prints the outcome code, phase, message, `refusal`, `reason`, `modelError` and diagnostics. The cancel step must answer `state: cancelled`. The wait is `STUDIO_REAL_SETTLE_S` (default 600 s). **Not re-run against etosd this round**, since the workers' `default` model is down until P0.1 switches it.
3. **Degraded model in the outcome.** `waiting` and `task_failed` outcomes gain `reason: "model_degraded"` and `modelError` when the record text or etos's `TaskInfo.error` names a degraded model (`degraded`, `auth_unavailable`, `access token has been revoked`, or `model` with HTTP 401/503/unavailable). A `failed` record's message now also appends etos's task `error` when the record text lacks it (`"<text> (etos: <error>)"`). A task etos reports as `waiting` with such an error is surfaced the same way by the status poll. Tests: unit `degraded_models_are_named_in_outcomes`; fake-node `a_degraded_model_is_named_in_the_outcome`.

### Media-op timeout (P2.2 live-run finding, applied)

`POST /v1/ops/generate` ran the node's op on the SDK's default 30 s timeout. `generate.image` on Echo gpt-image-2 takes longer, so Unity got a `transport` timeout and had to resend. **Chosen: hold the request.** Each op runs on its own client timeout `ops_timeout_secs` (default 300 s). Past that the companion answers **504 `transport`** with `data: {key, op}` and a hint naming the key, and resending the identical request reuses the key, so etops returns the result without generating again. The simpler hold was chosen over a 202-and-poll protocol because etops already dedupes by key, so a resend is the poll. It is documented in 04 §5. The etos proxy between Unity and the companion must allow requests that long. `ErrorBody` gains an optional `data` object for the key. Test `a_slow_media_op_is_held_up_to_the_op_timeout`:
- a 1 s op under a 2 s timeout is held and answered 200;
- a 3.5 s op gives 504 with the key;
- the identical resend returns 200 with the same key;
- every `generate.image` call carried that one key.

### `describe` and `max_cost_usd` (P2.2 live-run finding, row e; applied)

The companion used to put `max_cost_usd` into every op input, `describe` included, and etops refused that call with "unknown field `max_cost_usd`".

## 3. Open items and suggested etos patches (P0.1 owns etos)

1. ~~**`Ops::generate` bug**~~: fixed in etos `278ef9c`, and the companion uses the fixed method.
2. **Realtime refusal body is lost** (`sdk/rust` realtime `open`): an admission refusal answered over HTTP becomes `Error::Protocol("realtime connection failed: HTTP error: 503 …")`. Suggested patch: read the response body and return `Error::Refused{status, code, message, hint}`. Until then the companion makes one extra plain handshake to read the code (`voice.rs::probe_refusal`).
3a. **Task launch inside `POST /tasks`** (see "P0.1 host-run follow-ups" above): record the request→task row before launching, or launch detached, so a dropped request can neither strand a `starting` task nor allow a duplicate.
3. **`TaskRequest` has no `parent`.** The re-ask's parent is recorded in the ledger and named in `request.md` and `diagnostics.json`. Suggested patch: an optional `parent` that etos records on the task.
4. **04 §8's `command = "../../agent/target/release/gamecore-studio"` is invalid**, because etos refuses `..` in agent paths. The manifest uses `bin/gamecore-studio`, so **P0.1's `install.sh` must create** `studio/etos/agent/bin/gamecore-studio -> ../../../agent/target/release/gamecore-studio` (or copy the binary) before `etos agent install --link`. `bin/` is git-ignored.
5. **Mechanic outputs are flattened.** etos shares outputs by basename (≤64 files), so the package travels as `/outputs/package.tgz`. The stage runner extracts tar/tgz, picking the format from the magic bytes.
6. Voice provider status is `unknown` in hello until the first session, because no cheap realtime probe exists without opening a session.
7. The media-op idempotency key covers (changeSetId, op, spec, ceiling). Repeating an identical request returns the first result. For a variation, the client changes the spec (e.g. a `seed`) or the changeSetId.
8. The `IndexNode` in the companion's delta API and in `contextSlice` accepts two optional extensions, `rgKind` and `rgKey`. The companion strips them before schema validation and before packing `index-slice.json` for the worker. Deltas also accept `baseRevision`, `projectInfo` and `removals`.
9. **SDK source:** resolved by vendoring (see §1). When P0.1's patched SDK lands, the integrator runs `vendor-etos-sdk.sh <etos checkout>` with `studio/etos/etos.lock` naming the new commit, then rebuilds. If the patched `Error`/`Ops` APIs change shape, `src/error.rs` and `src/ops.rs` are the only places that touch them.
10. The Unity app cannot query `gc_*` with its key (point 11 above). P2.2 reads the index through its own index or the companion. If P2.2 needs RG reads from the editor, a companion `GET /v1/index/query` passthrough is a small addition.
