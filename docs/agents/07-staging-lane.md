# 07. Staging lane

Generated code never runs in the live Editor until it has passed in an isolated project and a creator has explicitly admitted it; the companion owns the stage, signs the verdict, and the Editor verifies that signature before it will enable Admit.

1. **Submit.** A `mechanism.propose` candidate (package plus proposal) goes to `POST /v1/stage`; a candidate the creator exported from the panel goes to `POST /v1/stage/app-candidate` as a `SignedCandidate{payloadBase64, signature}` with an HMAC-SHA256 over the app key and the domain `gamecore.stage.app-candidate/1`, plus the `X-GameCore-Stage-Key` header. The companion resolves the registered project (`[stage.projects]`), exports the project's single tracked baked world description into the sandbox read-only, and binds its hash to the request.
2. **Run.** The stage runs under Docker confinement (default; `Host` is an explicitly degraded operator mode that fails closed otherwise) with an offline NuGet cache, Unity licences from a private copy of the host's licence state, and attempt-scoped containers. Steps, in order: lexical scan (rules SG000 to SG012, `studio/stage/forbidden-rules.md`), checkers, `dotnet` rules tests, semantic analyzer (Roslyn), Unity EditMode, PlayMode smoke, determinism, budget. Output streams continuously, redacted; the slot allocator caps concurrent Unity instances.
3. **Verdict.** A verdict is accepted only when it is signed, `pass`, not partial, every step id passed, there are no forbidden hits, and `CatalogDelta{world, mechanisms, predicted}` is admission-ready, where `predicted = sha256("gamecore.catalog-set/1\n{world}\n{sorted fingerprints}")`. The Editor fetches it through `GET /v1/stage/{job}/verdict` and verifies it with `POST /v1/stage/{job}/verify` before enabling Admit. Since R10-A the signed world and the Editor's own fingerprint derive from the same authored source; a project whose bake is stale is refused early with `bake_stale`.
4. **Admit.** The creator's Admit is a durable admission with a 90 s compile deadline (180 s for removal) persisted as `compileDeadlineMs`; the resumer rebinds the authenticated session after the real package and domain reload, restores the world, runs the tri-state smoke (`Pending → Passed`) through the game's reviewed trusted extension registry (SADR-056), and only then marks the admission applied. A timeout rolls back, removes the package and leaves no pending record. Undo is a normal journal undo.
5. **Cancel.** `POST /v1/stage/{job}/cancel` (R8-A) is owner-scoped: it tears down the container, releases the slot, records `cancelled`, and issues no verdict.

Measured on the host (P4.2k and R10-A): cold stage about 160 s, warm about 77 s, creator admission 41 to 47 s including restored Play and smoke.
