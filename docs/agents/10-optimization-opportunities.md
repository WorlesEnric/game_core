# 10. Optimization opportunities

The biggest wins are in what the worker is given and how its mistakes are fed back, not in the transport; the list is ordered by expected effect on candidate quality per unit of work.

1. **Name the scene context in the prompt.** The bounded scene-context attachment (positions, hierarchy, AuthoringRefs) reaches the worker as "an attachment" and neither instruction file mentions it; the P4.2f ferryman clarification failed exactly because "its bounded scene attachment contains no objects and is truncated". Levers: list it in `gc-designer.md`, raise the 64 KiB / 128-object caps or make them selection-centric, and include measured facts the worker keeps asking for (NavMesh reachability was later supplied by hand). Files: `studio/etos/agent/workers/gc-designer.md`, `Packages/com.gamecore.studio.etos/Editor/AgentRequestBuilder.cs:69-155`, `studio/agent/src/desk.rs:580`.
2. **Teach the final-state validators in the prompt.** R11-A addresses one enrollment per definition in the designer's NPC prerequisites: `dialogue.createGraph` and `create` with `type: "dialogue.graph"` auto-enroll the new graph in the owning world's content set, so do not also append it to `definitions`; append the NPC definition to `npcs` exactly once. Duplicate `assign` appends are now idempotent (`alreadyListed: true`, existing index, no-op inverse), not a reason to emit redundant operations. GP-DLG-005 is also described to the worker, but the remaining GP-DLG-001, GP-DLG-003, content-closure and definition-validator rules still need broader guidance. Remaining lever: a compact rule digest generated from validator code into `common.md`; R11-A leaves `common.md` and the validators unchanged. Files: `studio/etos/agent/workers/gc-designer.md`, `studio/etos/agent/workers/tests/test_r6_b.py`, `Packages/com.gamecore.studio.core/Runtime/Model/ChangeSetValidator.cs:1333-1339`, `Packages/com.gamecore.studio.gameplay/Editor/DialogueClosureTools.cs`.
3. **Allow more than one re-ask, with structured diagnostics.** Today an invalid candidate gets exactly one `.r1` re-ask and `StaleContext` none; `diagnostics.json` is the only feedback. Levers: configurable re-ask count, diagnostics that quote the offending op and the rule's `data` (for example `unreachable` node ids), and a worker-side self-check against the schema before writing. Files: `studio/agent/src/desk.rs:26-30,1475-1551`, `studio/agent/src/candidate.rs`.
4. **Make clarification a conversation, not a terminal state.** `needs_clarification` ends the request; the answer is a brand-new request whose parent link exists only on the Unity side, so the worker restarts from scratch without the first task's reasoning. Levers: carry `parent` in `EditRequest` and attach the parent task's `request.md`, answer and outputs to the follow-up; or keep the task open and append the answer as an input. Files: `studio/agent/src/model.rs:575-664`, `Packages/com.gamecore.studio.ui/Editor/Tasks/TaskTrayView.cs:120-137`.
5. **Let the worker query before it answers.** The resource graph now holds every definition and dialogue node, but the prompt only shows two query forms and the index slice is depth 2 / 64 KB. Levers: a short query cookbook per tool group, a selection-rooted slice instead of a fixed depth, and a hint to query when the slice says `truncated`. Files: `studio/agent/src/desk.rs:584-600`, `studio/agent/src/index.rs:414-500`.
6. **Model binding.** Both workers run on `echo/gpt-6-sol` because the Opus alias is revoked at Echo; `gc-mechanic` writes C# packages and tests and would benefit most from a stronger model. Levers: restore the `default` alias when Echo allows it, or bind `gc-mechanic` separately; per-worker budgets are not declared in the manifest, so set one before raising the model tier. Files: `studio/etos/agent/agent.toml:35-47`, `studio/etos/models.toml.tmpl`.
7. **Trim the input packet.** Every request uploads the full tool catalog unless hello says the companion holds it, plus the index slice and selection; token cost scales with catalog size (12 plugin groups). Levers: send only the tool groups relevant to the selection's kinds, and cache `tool-catalog.json` on the node by revision. Files: `Packages/com.gamecore.studio.etos/Editor/EtosAgentGateway.cs:370-398`, `studio/agent/src/desk.rs:625-683`.
8. **Latency.** The companion waits up to 30 s on submit before switching to the follower, polls the topic with 20 s waits, and times out task opening at 180 s. Levers: stream `working` records into the tray earlier, and shorten the submit wait. Files: `studio/agent/src/desk.rs:126,271-273`, `studio/agent/src/config.rs:166-199`.
9. **Keep instruction changes deployable.** Worker `.md` edits only take effect through an immutable release and `etos agent upgrade --link`; a second, stale `studio/etos/workers/gc-mechanic.md` next to the Dockerfile is a trap. Levers: delete the duplicate, and add the worker tests to the release gate. Files: `studio/etos/install-state.py:164-257`, `studio/etos/workers/`.
10. **Voice.** Only final transcripts are shown; partials are not delivered by the provider for short takes. Lever: if interactive feedback matters, test a provider or VAD setting that emits partials before changing the UI. Files: `studio/agent/src/voice.rs`, `studio/etos/ops.toml.tmpl:10-16`.

Two documentation drifts to fix while tuning: `docs/studio/04-etos-integration.md` still calls describe unpriced (it is USD 0.01 operator) and quotes `wait_ms=60000` and 1000 records for topic polling (the code uses 20 s and 100).
